# Gap Analysis: Onboarding Feature

## 1. 現状調査

| ファイル | 役割 | 再利用可能性 |
|---------|------|-------------|
| `features/auth/pages/onboarding_page.dart` | プロフィール入力画面（新規ユーザー向け） | 名前が重複、チュートリアルとは別機能 |

- **状態管理**: Riverpod（StateNotifier, FutureProvider）

- **UI構造**: Stack + オーバーレイ、SafeArea、アニメーション
- **永続化**: Supabase認証のみ、ローカルストレージ未使用

### 1.3 不足している機能

| カテゴリ | 不足要素 | ステータス |
|---------|---------|-----------|
| **ローカルストレージ** | `shared_preferences`が依存関係にない | Missing |
| **チュートリアルUI** | オーバーレイ、ハイライト、ツールチップ | Missing |
| **状態管理** | オンボーディング完了状態のProvider | Missing |
| **初期化フロー** | チュートリアル表示判定ロジック | Missing |

## 3. 実装アプローチオプション

### Option A: 外部パッケージ使用

**候補パッケージ**:
- [onboarding_overlay](https://pub.dev/packages/onboarding_overlay) - FocusNodeベース、カスタマイズ性高い
- [flutter_tutorial_overlay](https://pub.dev/packages/flutter_tutorial_overlay) - ステップベース、シンプル

**実装内容**:
1. パッケージを依存関係に追加
2. 各画面のGlobalKeyを定義
3. ステップ設定を作成
4. shared_preferencesで完了状態管理

**Trade-offs**:
- ✅ 開発工数削減（推定: 3-4日）
- ✅ バグリスク低（実績あるパッケージ）
- ❌ カスタマイズ制限の可能性
- ❌ パッケージ依存度の増加

### Option B: フルカスタム実装

**実装内容**:
1. OnboardingOverlay Widget作成（Overlay API使用）
2. OnboardingStep モデル定義
3. OnboardingController（状態管理）
4. ハイライト計算ロジック（RenderObject.localToGlobal）

**Trade-offs**:
- ✅ 完全なカスタマイズ自由度
- ✅ 外部依存なし
- ❌ 開発工数大（推定: 7-10日）
- ❌ エッジケース対応が必要（キーボード、SafeArea等）

### Option C: ハイブリッドアプローチ（推奨）

**実装内容**:
1. `onboarding_overlay`パッケージをベースに使用
2. カスタムテーマ（AppTheme準拠）でラップ
3. shared_preferencesで状態永続化
4. 既存のdialogs.dartを離脱確認に再利用

**Trade-offs**:
- ✅ 開発工数と柔軟性のバランス（推定: 4-5日）
- ✅ 既存のUI/UXパターンとの統一
- ✅ 必要に応じてカスタマイズ可能
- ❌ 一部パッケージ依存

## 4. 実装複雑度とリスク

### 工数見積もり: **M (3-7日)**

| タスク | 見積もり |
|--------|---------|
| 依存関係追加・セットアップ | 0.5日 |
| オンボーディングステップ定義 | 1日 |
| ホーム画面オンボーディング実装 | 1.5日 |
| 録音画面オンボーディング実装 | 1日 |
| 状態永続化・初期化フロー | 1日 |
| テスト・調整 | 1日 |

### リスク評価: **Medium**

| リスク要因 | 影響 | 対策 |
|-----------|------|------|
| パッケージの互換性 | Flutter/Riverpodとの相性 | 事前にサンプル検証 |
| GlobalKey管理 | リビルド時の参照切れ | キー管理の設計をしっかり行う |
| 既存UIへの影響 | ホーム・録音画面の変更 | 変更を最小限に、復習ボタンのみ追加 |

## 5. 設計フェーズへの推奨事項

### 推奨アプローチ
**Option C: ハイブリッドアプローチ**を推奨

### 追加調査が必要な項目
1. `onboarding_overlay`パッケージの最新バージョン互換性確認
2. Flutter 3.10+での動作確認
3. 既存のオンボーディング画面（プロフィール入力）との名前衝突の解決方法

### 主要な設計決定
1. **状態永続化**: shared_preferencesを使用（シンプルで十分）
2. **復習ボタンの配置**: ヘッダー右上にアイコンボタンとして配置
3. **オンボーディングコンテンツ**: 各画面3-5ステップを想定
4. **命名規則**: 既存の`OnboardingPage`との衝突を避け、`TutorialOverlay`系の命名を採用
